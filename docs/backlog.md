# Feature Tracking

GitHub Issues are the source of truth for the HakoMachi feature backlog:

https://github.com/GeorgeHinch/HakoMachi/issues

This Markdown file is intentionally not a live backlog. Do not add feature entries, statuses, priorities, or implementation notes here. Keeping those fields in both Markdown and GitHub Issues creates avoidable drift.

## Agent Workflow

- Create and update feature work in GitHub Issues.
- Track state with the issue state, labels, assignees, milestones, and issue comments.
- When starting work, leave a short issue comment describing the planned scope if the issue is not already clear.
- When blocked or uncertain, leave a GitHub issue comment with the blocker and the exact decision needed.
- When complete, comment with the implementation summary and verification, then close the issue as completed.
- Do not mirror issue status back into this file.

## Issue Shape

Feature issues should remain agent-ready by including the product goal, acceptance criteria, likely starting points, and known dependencies directly in the GitHub issue body or comments.
